# VM Design

Портфоліо Maryna Vashchenko — interior architect. Côte d'Azur · Monaco · Італія.

Astro + TypeScript, чистий CSS на токенах, без фреймворків.
Уся інтерактивність — ~5.7 KB інлайн-JS (2.1 KB gzip) на найважчій сторінці.

## Запуск

```bash
npm install
npm run dev
```

## Форма контактів

Листи йдуть через **Formspree** — без власного сервера й без поштових
ключів у фронтенді.

```bash
cp .env.example .env    # і вписати id форми
```

`PUBLIC_FORMSPREE_ID` — це кінець адреси з кабінету formspree.io
(`https://formspree.io/f/xayzwqrb` → `xayzwqrb`). Ключ **не секрет**: він
за визначенням видимий у розмітці, бо стоїть в `action` форми. Тому
префікс `PUBLIC_`, а не звичайна змінна.

Отримувача листів задає не код, а налаштування форми в кабінеті
Formspree. Адреса, показана на сайті (`SITE.email`), — окрема річ: це
посилання `mailto:` у блоці контактів.

Для деплою ту саму змінну треба додати в Cloudflare Pages:
Settings → Environment variables → Production.

Без змінної збірка не падає, але друкує попередження, форма не надсилає
й одразу пропонує написати листом. Перше звернення Formspree притримає,
доки адресу отримувача не підтвердять листом від них.

## Пайплайн контенту

Сирі матеріали від замовниці лежать у `.source/` (не версіонується, ~1.3 ГБ).

Друга партія (вересень 2026) замінила першу: 357 фото замість 151, плюс
новий проєкт Germany Kassel, виставкові стенди та фото процесу.

```bash
# 0. Розпакувати партію від замовниці (лікує кодування імен, чистить мотлох macOS)
python scripts/unpack-source.py "C:/Users/andrb/Downloads/Project Marina new.zip"

# 1. Підготувати зображення: поворот за EXIF, ЗНЯТТЯ GPS, ресайз, домінантний колір
node scripts/prepare-images.mjs --all  # уся партія — щоб було з чого відбирати
node scripts/write-curation.mjs        # відбір за індексами контактних аркушів
node scripts/prepare-images.mjs        # тільки відібране + прибирання зайвого

# 2. Перегенерувати контент-файли (разово, до появи авторських текстів)
node scripts/gen-content.mjs

# 2b. Розкласти 3D-візуалізації за типом приміщення
node scripts/prepare-renders.mjs

# 2c. Ретуш креслень: прибрати дані клієнтів і віддати сторінки растром
python scripts/redact-drawings.py --dry   # спершу ЗАВЖДИ сухий прогін
python scripts/redact-drawings.py

# 3. Перебудувати геометрію карти (Natural Earth + регіони FR/IT)
node scripts/build-map.mjs

# 4. Оновити локальні шрифти
node scripts/fetch-fonts.mjs
```

**Важливо про приватність.** Сирі фото містили GPS-координати житла приватних
клієнтів (15 GPS-тегів у кадрі). `prepare-images.mjs` знімає всі метадані —
не додавайте `.withMetadata()` до пайплайну.

Оригінальні PDF у `.source/Project PDF/` **ніколи не потрапляють у `dist/`**.
На сайт іде тільки растр після `scripts/redact-drawings.py`.

**Про ретуш креслень.** Малювати прямокутник поверх тексту в самому PDF —
хибний шлях: текстовий шар лишається і витягується копіюванням або
`pdftotext`. Тому сторінка спершу растеризується, і лише потім
зафарбовуються клітинки `CLIENT` / `ADRESSE`. Деталі — у
`scripts/redact-drawings.mjs.md`.

Зафарбовано 128 зон на 193 сторінках: прізвища замовників, адреси житла
у клітинках `CLIENT`/`ADRESSE`, а в комплекті по віллі ще й адреса будинку
поза титульним блоком — саме її попередній ручний огляд пропустив.

Скрипт має вбудований контроль витоку: кожна сторінка перевіряється на
список заборонених рядків, і за будь-якого збігу поза зафарбованою зоною
скрипт падає з ненульовим кодом.

**Самі ці рядки у git не зберігаються.** Вони лежать у
`.source/redaction.json` разом із назвами вихідних PDF — у назві одного з
файлів прізвище замовника стоїть просто так. Тримати перелік того, що ми
ховаємо, у публічному репозиторії було б безглуздо: він відтворював би
рівно ті дані, заради яких уся ретуш і робиться.

```jsonc
// .source/redaction.json — поза git
{
  "sets": [
    { "file": "<назва PDF>", "slug": "<slug комплекту>",
      "label": "<підпис на сайті>", "project": "<slug проєкту>" }
  ],
  // регулярні вирази; у JSON зворотна коса подвоюється
  "forbidden": ["\bПРІЗВИЩЕ\b", "вулиця\s+Назва"]
}
```

Без цього файлу скрипт не запускається навмисно: якби він допускав
порожній список, контроль витоку тихо став би заглушкою, що завжди
каже «чисто». **Додавай туди кожне нове ім'я чи адресу з наступних
партій.**

## Оптимізація

Що зроблено і чому — щоб випадково не відкотити.

**Ассети-сироти.** Astro копіює в збірку оригінал КОЖНОГО зареєстрованого
зображення, навіть якщо посилання на нього немає. `import.meta.glob` реєстрував
усе, що збігалося з шаблоном, і в `dist` лежало 150 мертвих файлів на 25.8 МБ.
Лікується двома правилами:

- **не тримати в `src/assets` того, що не публікуємо** — непублічні аркуші
  креслень переїхали в `.drawings-full/` поза `src/`;
- **явні імпорти замість глоба** там, де використовується не все —
  `src/lib/services.ts`.

**Геометрія карти.** Абсолютні координати з десятковою частиною
(`L332.0 321.5`) давали 38 КБ на сторінку — половину стисненого HTML головної.
`encodePath()` у `scripts/build-map.mjs` пише відносні дельти цілими числами
(`l2-2`), курсор ведеться по вже округлених значеннях, щоб контур не «повз».
Результат: 33 → 12 КБ у JSON, HTML головної 27.4 → 17.8 КБ gz.

**AVIF — лише для першого екрана.** `<Picture formats={['avif']}
fallbackFormat="webp">` стоїть на чотирьох кадрах, що визначають LCP: hero
головної, титульні кадри проєкту й Christina, портрет. Виграш 38–45% ваги
(hero: 81 → 50 КБ). Решта зображень лишається WebP: вони ліниві, а AVIF на
1500+ файлів додав би ~13 хвилин до кожної збірки.

`fallbackFormat="webp"` важливий: типовий запасний формат `<Picture>` — jpg,
і він додавав 84 файли на 12.5 МБ заради браузерів, яких уже немає.

**Контраст на фоні контакту.** Кадри моря дають найсвітліший піксель L≈0.74;
під початковим затемненням підписи полів форми виходили на **1.57:1** — провал
AA. Виправлено `filter: brightness(0.4)` на самому зображенні плюс легший
градієнт: у найгіршій точці `--bone` 10.7:1, `--muted-inv` 4.7:1. Фото при
цьому видно краще, ніж під суцільним затемненням 0.9.

## Дизайн-система

Палітра виведена, не підібрана:

- `--ink #2b2a29` — виміряний із `logo.png` (53% пікселів знака)
- нейтральна шкала — та сама тепла вісь hue 30–35°
- `--accent #6f5a41` / `--accent-inv #b5a384` — виміряні з фотографій проєктів
  (домінантна тепла смуга hue 30–35°: латунь, дуб, травертин)

Усі текстові пари перевірені на WCAG 2.1 AA (≥ 4.5:1). Деталі — у `src/styles/tokens.css`.

Типографіка: Instrument Serif (display) + Inter Tight (текст), локальні woff2,
сабсети latin + latin-ext, критичний шлях 64 KB.

## Карта

Власний inline SVG замість Leaflet (42 KB + тайли) чи MapLibre (230 KB).
Пан, зум, pinch, клавіатура, межі кадру, контрмасштаб маркерів — 3.2 KB.

Ніцца, Канни й Монако вміщаються в ~40 км, що на оглядовому масштабі
дає ~27 px, тож вони згортаються в кластер «Côte d'Azur» і розкладаються
при наближенні (`CLUSTERS[].splitAt` у `src/lib/map.ts`).

Кадр охоплює Францію, Італію та Німеччину (північна межа 54°, бо Kassel
на 51.3° впирався у верхній край). Підсвічені регіони: Île-de-France,
Provence-Alpes-Côte d'Azur, Lombardia, Emilia-Romagna, Lazio.

**Гонконг за кадром** — при цій проєкції він лягає на x≈4900 при ширині
полотна 1000. Такі локації `buildMarkers()` віддає окремим списком `beyond`,
і вони виводяться текстом під картою. Світова карта була б на 90% порожня.

## 3D-візуалізації

Розділ `/visualisations` згрупований **за типом приміщення, а не за об'єктами** —
так просила замовниця. Референс, який вона надіслала: секція AMBIENTI на
pistoremarmi.com (звідси легкий нахил карток, приглушений відносно оригіналу).

Тип визначається з імені файлу (замовниця іменувала їх російською).
Кадри без змістовної назви — `IMG_*`, `unnamed` — розкладені вручну після
перегляду; таблиця у `scripts/prepare-renders.mjs`, константа `BY_FILENAME`.

Розділи й наповнення: Kitchen & Living 29 · Bedrooms 27 · Bathrooms 26 ·
Hallways 13 · Children's Rooms 8 · Dressing Rooms 6 · Studies 3.

**Увага:** 34 зі 112 рендерів мають коротку сторону < 1000 px
(найгірший — 1280×504). На великому екрані вони будуть м'якими.
Варто попросити оригінали у вищій роздільності.

## «До / після»

Сім проєктів мають кадри стану до робіт. Найповніші — Roma (8), La Villa (7),
Monza (6), Kassel і Cannes (по 5).

Подача задається в `beforeAfter.mode`:

- `slider` — повзунок-витирач. Вимагає, щоб «до» і «після» були зняті
  **з однієї точки**, інакше картинка стрибає. Перевірено: зараз цій умові
  відповідає лише вітрина Roma.
- `pair` — два кадри поруч. Чесно працює за будь-якого кадрування; стоїть
  скрізь за замовчуванням.

Щоб отримати слайдери на решті проєктів, потрібно, щоб Марина вказала
відповідність кадрів — вона знає ці приміщення.

індекс, і сюди.

## Креслення

Секція «Documentation» усередині сторінки проєкту — комплект показується там,
де він має сенс, а не окремим розділом.

Публічно видно **перші 8 аркушів**, решта — за запитом через форму
(`PUBLIC_PAGES` у `src/lib/drawings.ts`). Причина: 193 сторінки робочої
документації цікавіші конкуренту, ніж клієнту. Щоб показати все — підняти число.

Прив'язка комплекту до проєкту — поле `project` у `src/data/drawings.json`
(джерело — `SETS` у `scripts/redact-drawings.py`). Прив'язані всі сім.

Проєкт може мати **кілька комплектів**: у Saint-Paul-de-Vence три квартири,
кожна зі своїм. Вибірка тоді береться з кожного комплекту окремо, щоб
показати всі три, а не перші вісім аркушів першої.

## Аркуші пар «до / після»

```bash
node scripts/pairing-sheet.mjs
```

Кладе у `.pairing/` по аркушу на проєкт: зверху всі кадри «до» з номерами
`B1…Bn`, знизу всі «після» `A1…An`. Замовниця підписує пари у форматі
`B3 → A7`, і кожна така пара вмикає слайдер замість простого показу поруч.

## Мови

EN — джерело, без префікса. FR · IT · RU · UA — з префіксом, поки що з
`fallbackType: 'rewrite'`: локалізований URL віддає англійський вміст
на своєму ж URL. Коли з'являться переклади — класти як
`src/content/projects/fr/<slug>.md`, решта підхопиться сама.

Порядок доливання за реальними ринками: EN → FR → IT → RU → UA.

Блоки робіт: Residential · Commercial · Exhibitions · Visualisations.
Кожен веде на свою сторінку, тож головна сама працює як фільтр і окремий
UI фільтрів не потрібен.

**Свайп — на CSS `scroll-snap`**, тому палець, трекпад і скролбар працюють
без скриптів. `scripts/swiper.ts` додає лише стрілки, і показує їх тільки
тоді, коли стрічка справді ширша за екран.

Картка-«плита»: `rotateY(-7deg)` плюс псевдоелемент бічної грані. Під
`prefers-reduced-motion` нахил і грань вимикаються.

## Форма

Formspree, звичайний `<form method="POST">`. Без JS форма надсилається
і приземляє на сторінку Formspree; `scripts/contact-form.ts` перехоплює
submit і показує статус на місці, бо власний «дякую»-екран у безкоштовному
плані недоступний.

Ліміт безкоштовного плану — **50 надсилань на місяць**. Ключ форми не є
секретом: на відміну від ключа поштового API, він і має бути в розмітці.
